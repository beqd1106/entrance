# Houserule（Houserule）

**打ってから、行く。** — 全国の雀荘が「オンライン支店」を持ち、
ユーザーが店のハウスルールを実際に打って体験してから来店できるプラットフォームの試作です。

オンライン麻雀で雀魂と競争することが目的ではありません。**店舗への送客と、来店前の不安をなくす体験の入口**を作ることがコアです。

---

## 1. すぐ動かす

```
start.bat をダブルクリック
→ ブラウザで http://localhost:5173/ が開きます
```

手動で起動する場合：

```bash
node server.js 5173      # Node.js 18以上（動作確認は v22.17.0）
# → http://localhost:5173/
```

ビルド・npm install は不要です（依存パッケージゼロ・純粋なES Modules）。

### 主要な画面

| URL | 内容 |
| --- | --- |
| `#/` | OP画面（何をするかを選ぶ入口。1画面で完結・スクロールなし） |
| `#/table` | 卓を立てる（人数→ルール→よく変える設定→対局開始） |
| `#/search` | 店舗とルールの横断検索（言葉で探す） |
| `#/stores` | 店舗検索（キーワード＋ルール条件で絞り込み） |
| `#/store/goto_kan` | 店舗ページ（五等サンマ館） |
| `#/play?preset=store_goto_kan` | その店のルールでCPU対戦 |
| `#/editor?preset=standard4` | 店舗ルールエディタ（JSON不要） |
| `#/dashboard` | 店舗側の管理画面（公開前チェック・店舗情報の設定） |
| `#/compare` | 2ルールの比較表 |
| `#/about` | サービス紹介（旧ホーム。デモ店舗とプリセットの一覧） |
| `#/manual` | 使い方 |
| `tiles-preview.html` | 牌面（インラインSVG）の一覧 |

起動直後は店舗一覧ではなく**機能を選ぶOP画面**を出す。
「打つ」導線（卓を立てる／前回の続き）を最上段に置き、
店舗さがし・ルール設定・比較・店舗管理はその下に並べている。

## 2. テストの実行

```bash
node test/run-tests.js          # 単体テスト（役・点数・進行・ハウスルール）
node test/verify-shanten.js     # 向聴数計算を素朴な参照実装と突き合わせ
node test/sim.js 12             # 全22プリセットをCPU自動対局で整合性検証
node test/sim.js 300 standard4  # 1プリセットを300対局（約2,800局）
```

直近の結果：

- 単体テスト **58件すべて成功**
- 向聴数計算 **5,000ケースが参照実装と完全一致**
- CPU自動対局 **1,500対局／約9,900局**（一般四麻・四麻館・特殊牌館・五等サンマ館・ゆる五等）で
  牌の増減・同一牌5枚・点棒不整合・進行停止・0翻和了 **いずれも0件**（`test/sim-result.txt`）

## 4. 置いた仮定（不明点は止めずに仮置きしています）

実店舗のルールは店ごとに細部が異なるため、以下は**「よく見られる形」を採用した仮置き**です。
設定で変更できるようにしてあるので、ヒアリング後に数値を差し替えれば足ります。

| 項目 | 置いた仮定 | 備考 |
| --- | --- | --- |
| アリスの開始位置 | ドラ表示牌の隣（槓ドラになる位置）からめくる | 王牌の端から始める設定にも切替可 |
| アリスの継続 | 一致する限り継続、最大4枚 | 枚数・上限とも設定可 |
| アリスの刻子扱い | 手牌にある枚数分カウント（例：対子なら2倍） | 「1回のみ」にも切替可 |
| チューリップ | アリスの拡張として実装（現物＋数牌は±1・字牌は輪の隣を一致扱い） | 別設定として独立管理 |
| 白ポッチ | 既定は「リーチ後のツモ時のみオールマイティ」＋祝儀 | 常時／ツモ時にも変更可 |
| 三麻のツモ損なし（丸取り） | 4人麻雀と同額になるよう不足分を支払者へ均等按分し、100点単位で切り上げ | 店により処理が異なるため要確認 |
| 華牌の効果 | 春＝即時BP（オール）／夏＝打点1ランクアップ／秋＝5牌がダブドラ／冬＝和了時アリス | すべて種類別に変更可 |
| 秋の「5牌ダブドラ」 | 手牌・副露の5の牌1枚につきドラ+1 | 赤金限定にする実装も可能 |
| 王牌の補充 | 嶺上牌4枚を使い切った後は海底から補充（牌の総数は保存） | 北抜き・華牌が多い三麻での実務的処理 |
| 完全先付け | 「すべての待ちで役が確定しているか」で近似判定 | 厳密な流派差はヒアリングで調整 |
| 東天紅の点数表 | 翻計算を1/1000する近似（役満のみ固定点） | 独自の点数表を持つ店もあるため要確認 |
| 東天紅のガリ | 1枚4点として和了者の点に加算。5筒・5索は常時ドラ | 「ガリは1点役」とする流派もある |
| 少牌マイティの未対応分 | 「萬子の混一色は役満」「お多福」「無」は未実装 | 公式ルールにあるが、判定に追加の状態が要る |
| ロケット三麻の各種数値 | 実践者の記録をもとにした代表値 | 店ごとの差が大きく、公式ルールが存在しない |
| ロケット系の祝儀額 | 実践者記録をもとにした代表値 | 店舗ヒアリングで差し替え |
| ローカル役の翻数 | 一般的とされる値を既定に | 採用可否・翻数が店舗ごとに分かれるため設定必須 |
| 三連刻と一色三順 | 同じ牌姿の別解釈のため、両方有効なら高い方を採用 | 通常はどちらか一方だけを採用する運用を推奨 |
| 十三不塔・八連荘 | 配牌／連続和了の状態から近似判定 | 厳密な流派差は要確認 |
| 形式テンパイ非採用時 | 現状はテンパイ扱いのまま（将来対応と明記） | 採用店が多いため既定はON |
| 順位点 | 沈みウマ有効時はトップのウマを他家合計の裏返しで確定（完全順位制） | ゼロサムを保証 |
| 清一色ゲームの牌構成 | 全自動卓の2セットを混ぜた108枚（筒子36・索子36・5萬8枚・字牌28） | 5萬の枚数や字牌の枚数は店により差がある |
| 清一色ゲームの5萬 | 通常の数牌として扱う（**ヤオチュウ牌扱いは未対応**） | 実ルールでは么九牌として国士に使える店がある |
| 清一色ゲームのウマ | ワンスリー（2着+1／ラス-3）をゼロサムで確定 | 沈みウマはラスに二重適用されるため未使用 |
| 背一色 | 手牌・副露のすべての牌の裏が同色でダブル役満 | 翻数・採用可否は `localYaku` で変更可 |
| ゲーム内ポイント（BP） | **すべて非換金・ゲーム内専用**。現金・景品と交換しない | 法務上の安全側設計（要専門家確認） |

デモ店舗3件は**すべて架空**です。実在店舗のハウスルールをそのまま転載していません。

## 6. iPhoneで使う（PWA）

1. PCで `start.bat` を起動し、PCのIPアドレスを確認（例 `192.168.1.10`）
2. iPhoneのSafariで `http://192.168.1.10:5173/web/` を開く
3. 共有ボタン →「ホーム画面に追加」
4. アイコンから起動 → **横向きにして対局**（横持ち前提で1画面に収まります）

- オフライン対応（Service Workerでエンジンをキャッシュ）
- セーフエリア（ノッチ）対応、縦持ち時は回転をうながす表示
- App Store配布の手順は `docs/06_iPhoneアプリ化計画.md`（Capacitorでのラップを推奨）
- 本番配信は HTTPS が必要です（Vercel / Cloudflare Pages 等）

## 7. iPhoneアプリ（TestFlight配信）

Macなしで、GitHub Actions から TestFlight まで配信できます。

```bash
node scripts/build-ios-www.js          # Web資産を ios/www へ配置
gh workflow run ios-verify.yml         # 署名なしのビルド検証（シークレット不要）
gh workflow run ios-testflight.yml -f version=1.0.0   # TestFlightへ配信
```

- `ios/` … XcodeGen定義＋Swiftシェル（WKWebView＋独自スキーム配信）
- WebのUIとルールエンジンを**そのまま同梱**。Web側を直せばアプリ側も直ります
- **完全オフライン動作**（通信ゼロ）・**横持ち固定**・全画面
- 必要なシークレットと初回セットアップ手順は `docs/07_TestFlight配信手順.md`

## 8. 注意事項

- 本リポジトリのゲーム内ポイント（BP）は**非換金・デモ用・ゲーム内専用**です。
  現金・景品・電子マネー等との交換、送金、払い戻し、賭け金設定はいずれも実装していません。
- 賭博罪・景品表示法・資金決済法・風営法との関係については本資料で論点を整理していますが、
  **法的な最終判断は必ず弁護士等の専門家に確認してください（要専門家確認）**。
- 実在の店舗名・ルールを掲載する場合は、必ず当該店舗の許諾を得てください。
