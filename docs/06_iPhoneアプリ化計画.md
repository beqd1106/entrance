# iPhoneアプリ版の作り方

> 結論：**今日からiPhoneで「アプリとして」使えます（PWA）。**
> App Store配布が必要になった段階で、同じコードのままCapacitorでネイティブ化するのが最短です。

---

## 1. いま出来ていること（PWA・実装済み）

| 項目 | 内容 |
| --- | --- |
| ホーム画面に追加 | Safariで開く →「共有」→「ホーム画面に追加」でアイコンが並びます |
| 全画面起動 | Safariのアドレスバーが消え、ネイティブアプリと同じ見た目で起動します |
| **横持ち前提のレイアウト** | 卓・河・手牌・行動ボタンが**1画面に収まり、スクロール不要** |
| オフライン対応 | Service Workerでエンジン一式をキャッシュ。**機内モードでもCPU対戦できます** |
| セーフエリア対応 | ノッチ／ホームインジケータを避けて配置（`env(safe-area-inset-*)`） |
| アイコン | 一萬をモチーフにしたSVGアイコン（通常・マスカブル） |
| 縦持ち時の案内 | 「横向きにすると卓が広く使えます」を表示 |

### 追加した実装

```
web/manifest.webmanifest   アプリ名・アイコン・全画面・landscape指定
web/sw.js                  オフラインキャッシュ（アプリシェル＋エンジン）
web/icons/*.svg            アイコン3種
web/index.html             apple-touch-icon / apple-mobile-web-app-capable など
web/css/style.css          横持ち専用レイアウト＋セーフエリア
```

### 試す手順（実機）

1. PCで `start.bat` を起動し、PCのIPアドレスを確認（例 `192.168.1.10`）
2. iPhoneのSafariで `http://192.168.1.10:5173/web/` を開く
3. 共有ボタン →「ホーム画面に追加」
4. ホーム画面のJANDOORアイコンから起動 → **横向きにして対局**

> 本番では HTTPS が必要です（Service Worker と「ホーム画面に追加」の要件）。
> Vercel / Cloudflare Pages に置けば自動でHTTPSになります。

## 2. ネイティブ化の選択肢

| 方式 | 開発量 | App Store配布 | プッシュ通知 | 既存コード | 推奨度 |
| --- | --- | --- | --- | --- | --- |
| **A. PWAのまま** | ゼロ（完了） | ×（ストアには出ない） | △（iOS16.4+で可） | そのまま | **PoC〜フェーズ1はこれで十分** |
| **B. Capacitorでラップ** | 小（1〜2週） | ○ | ○ | **そのまま流用** | **フェーズ2の本命** |
| C. React Native / Expoで作り直し | 大（2〜3ヶ月） | ○ | ○ | UIは作り直し。ルールエンジンは移植可 | 将来、対局UIを作り込む段階で検討 |
| D. Swift（フルネイティブ） | 特大 | ○ | ○ | 全て作り直し | 現時点では非推奨 |

### なぜ B（Capacitor）が本命か

- 本アプリの資産は**ルールエンジン（`src/`）とハウスルールのデータ構造**であって、UI実装ではありません。
- Capacitorは既存のWeb実装をそのままiOSアプリとして包めるため、**エンジンもUIも作り直しになりません**。
- 店舗ページ・ルール検索はWebのままSEOに効かせ、**アプリ版は対局に集中**という分担ができます。

### Bの具体的な手順（想定1〜2週間）

```bash
npm init -y
npm i @capacitor/core @capacitor/cli @capacitor/ios
npx cap init JANDOOR com.example.jandoor --web-dir=web
npx cap add ios
npx cap sync
```

- `capacitor.config.json` で `orientation: landscape`、`backgroundColor` を指定
- スプラッシュ／アイコンは `@capacitor/assets` で生成
- ビルドは **Macがなくても可**（Codemagic または GitHub Actions の macOS ランナー）
  ※ 既に他プロジェクトで `XcodeGen + GitHub Actions → TestFlight` の運用実績があるため、同じ流れに載せられます
- 必要なもの：Apple Developer Program（年 $99）、Bundle ID、証明書・プロビジョニング

## 3. 横持ち（landscape）前提の設計方針

iPhoneを横に持ったときの実サイズは **844×390pt 前後**（iPhone 14/15 系）。
縦幅が390ptしかないため、次の方針で組んでいます。

| 課題 | 対応 |
| --- | --- |
| 縦の余裕がない | ナビゲーションを非表示にし、卓を画面いっぱいに使う |
| 手牌が押しづらい | 手牌と行動ボタンを**画面最下部に固定**し、親指の届く位置に配置 |
| 情報量が多い | ルール要約とログを右カラム（190px）にまとめ、卓は左側に集約 |
| ノッチ | 左右に `env(safe-area-inset-left/right)` を確保 |
| 牌が小さくなりすぎる | 手牌は30px相当、河は14px相当と**役割ごとにサイズを分離** |
| 誤タップ | 行動ボタンは高さ32px以上・角丸ピル形状で間隔を確保 |

### 今後の横持ち向け改善（フェーズ2）

- 手牌のドラッグ&ドロップ（つまんで捨てる）
- 長押しで牌の説明（この店の特殊牌は何か）を表示
- 触覚フィードバック（Haptics）— Capacitor化後に対応
- 画面回転ロック（landscape固定）— PWAのmanifestで指定済み、ネイティブでは確実に固定可能

## 4. App Store 申請時の注意（**要専門家確認**）

麻雀アプリはガイドライン上、**ギャンブルとの線引き**が最重要です。

| 論点 | 対応方針 |
| --- | --- |
| 賭博性の有無 | 現金・賭け金・換金ポイントを**一切実装していない**。BPは非換金・ゲーム内専用 |
| 年齢レーティング | 「シミュレーテッドギャンブル」に該当する可能性があるため、**17+**での申請を想定 |
| App内での実店舗誘導 | 店舗情報・来店導線は情報提供の範囲に留める。レート表記はしない |
| 位置情報 | 使う場合は用途を明示（店舗検索のみ）。MVPでは未使用 |
| 未成年対策 | 実店舗は18歳未満入店不可が通例のため、年齢確認の導線を検討 |
| 個人情報 | プライバシーポリシー・App Privacy の申告が必須 |

> 上記は一般的な整理であり、法的・審査上の判断ではありません。
> 申請前に**弁護士等の専門家および最新のApp Store Reviewガイドライン**を必ずご確認ください（**要専門家確認**）。

## 5. 進め方の推奨

| フェーズ | やること | 期間 |
| --- | --- | --- |
| いま | **PWAのまま**、協力店1店で公開。iPhoneのホーム画面追加で使ってもらう | 即日 |
| フェーズ1 | HTTPS公開（Vercel等）、実機での横持ち調整、来店計測 | 3〜4週 |
| フェーズ2 | Capacitorでラップし、TestFlightで店舗スタッフに配布 | 1〜2週 |
| フェーズ3 | App Store申請（17+）、プッシュ通知でイベント告知 | 2〜4週 |

**ポイント**：ストア配布は「送客に効く」と分かってからで十分です。
PWAならURLを送るだけで試してもらえるため、検証速度が圧倒的に速くなります。
