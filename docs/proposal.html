01

この企画の本質

麻雀アプリではなく、雀荘の集客・体験設計プロダクトです。

初来店を止めているのは
「強さ」ではなく「分からなさ」。

USER

ユーザーが行けない理由

  • その店のルールが分からない（白ポッチ？　北抜き？）
  • 知らないルールで場を止めるのが怖い
  • 客層・雰囲気が事前に分からない
  • 特殊ルールは練習する場がない
STORE

店舗が困っていること

  • 新規が入ってこない／常連が固定化
  • 毎回スタッフが口頭でルール説明している
  • ルールの独自性が差別化に使えていない
  • オンラインで「体験」を渡す手段がない
この不安は、ルールを読ませても消えません。打たせると消えます。 Houseruleは「その店のルールで実際に1半荘打てる」ことを、来店前の標準体験にします。

差別化：ルールが「動くデータ」であること

ゲームエンジンは店の名前を一切知りません。店の追加＝データ1件の追加です。

店舗ルールプリセット（データ） ↓ ルール設定（全項目のスキーマ） ↓ ルールエンジン 基本 / ドラ / 役 / 特殊牌 / 祝儀 / カスタム ↓ ゲームエンジン 牌 / 手番 / 行動 / 手役 / 点数

普通に作ると、店が増えるたびに作り直しになります。 最初からルールをデータにしたので、2店舗目以降は設定を1件足すだけです。

ルール説明は自動生成される

店が設定すると、初来店者向けの説明文ができあがります。書く手間はゼロです。

一般ルールとの差分モード（主役）

「全部読め」ではなく「違うのはここだけ」

対局の長さ半荘戦 → 東風戦
持ち点25,000点 → 35,000点
返し点30,000点 → 40,000点
表ドラ表示牌1枚 → 2枚
白ポッチなし → あり
華牌（春夏秋冬）なし → あり

実出力：五等サンマ館は一般三麻と19項目だけ違う

全文モード（抜粋・実出力）

  • 三人麻雀の東風戦です。
  • 35,000点持ち40,000点返し、ウマは 0 / 0 / -20 です。
  • 順位点のみの完全順位制です（素点は成績に反映されません）。
  • 白ポッチが1枚入っています。リーチ後のツモ時にオールマイティ牌として使えます。
  • 北は抜きドラです。他家が抜いた北でロンはできません。
  • 華牌「春」：抜いた枚数×1BPを即時獲得（オール）
  • 華牌「夏」：和了時に打点が1ランクアップ
  • 華牌「秋」：5の牌がダブルドラになる
  • 華牌「冬」：和了時にアリス発動（一致1枚あたり2BP）

法務・運用リスク

先に安全側で設計しています。ただし最終判断は要専門家確認です。

MVPで実装しないもの

  • 現金・金券を賭ける機能
  • 対局結果に応じた金銭・景品の付与
  • 換金可能ポイント／ポイントの譲渡・売買
  • 送金・払い戻し
  • 賭け金の設定
  • 実金額・レートの表示

MVPで実装するもの

  • BP（ゲーム内ポイント）＝非換金・ゲーム内専用。UIに常時明記
  • 来店スタンプ／チェックイン／イベント参加記録
  • 称号／来店回数／店舗別レベル（記録のみ・報酬なし）
  • 人間同士の対戦を実装しない＝談合・複アカを構造的に回避
論点内容対応
賭博罪財物・財産上の利益を賭ける行為金銭・賭け金の概念を実装しない
換金性ポイント換金・譲渡可能なポイントはリスクが高い非換金・譲渡不可・ゲーム内専用
景品表示法景品類の限度額・有利誤認物品の賞品を出さない（称号のみ）
資金決済法前払式支払手段の届出等有償ポイントを発行しない
風営法実店舗は許可制許可店舗のみ掲載。レート表記をしない
未成年・依存18歳未満／長時間利用年齢確認、プレイ時間表示、相談窓口の掲示
個人情報会員情報・来店履歴収集の最小化（来店は回数のみ）
特に注意：オンラインの成績と実店舗の特典を直結させないこと。 「オンラインで1位＝店で割引」は避け、「来店回数で称号」など行動ベースに留めます。
本資料は論点整理であり法的助言ではありません。実施前に必ず弁護士等へご確認ください（要専門家確認）。
