# オンライン対戦（設計と費用）

同じハウスルールを、離れた相手と一緒に打てるようにする。
店の常連同士でも、これから行く店のルールを友人と試すのでも使える。

---

## 1. 費用の見立て（結論：月100円台）

上限は月2万円。実際に使う分はその1000分の1以下で収まる。

四人打ちの半荘1回を、40分・行動1000回として数える。

| 項目 | 単価 | 半荘1回あたり |
| --- | --- | --- |
| WebSocket 接続時間 | $0.25 / 100万接続分 | 4人×40分＝160接続分 → 約0.006円 |
| WebSocket メッセージ | $1.00 / 100万通 | 1000行動×4人＝4000通 → 約0.6円 |
| Lambda 実行 | 100万回/月まで無料 | 1000回（無料枠内） |
| DynamoDB | 書いた分だけ | 1000書き込み → 約0.2円 |

**半荘1回 ≒ 1円弱。** 月に1000半荘打たれても月1000円に届かない。

### それでも歯止めを置く

費用が壊れるのは「使われたとき」ではなく「暴走したとき」。
再接続を繰り返すクライアントや、放置された部屋が積み上がる形が危ない。

| 歯止め | 値 | 理由 |
| --- | --- | --- |
| 同時に開ける部屋 | 20室 | 超えたら新規作成を断る。テスト中はこれで十分 |
| 1部屋の人数 | 4人まで＋観戦なし | 増える経路を作らない |
| 無操作での切断 | 5分 | 席を立ったままの接続を残さない |
| 部屋の寿命 | 2時間（TTLで自動削除） | 放置された部屋を溜めない |
| 1日のメッセージ数 | `DAILY_WS`（既定20万） | 全体の硬い天井。超えたらその日は新規対局を断る |
| Lambda 同時実行 | 10 | 暴走しても並列に増えない |

いずれも既存の `underGlobalDailyLimit` と同じ考え方で、
**上限に当たったら断る**（課金が伸び続ける経路を作らない）。

## 2. 段階を分ける

### 第1段（いま作るもの）：部屋に集まって打つ

サーバは**順番を決めて配る係**に徹する。
対局そのものは、各自の端末が同じ engine を同じ種で動かして進める。
サーバが行動の順番を決めるので、全員の画面は必ず一致する。

- 部屋を作ると4桁の部屋番号が出る。相手はその番号で入る
- 空いた席はAIが埋まるので、2人でもすぐ打てる
- 通信が切れても、行動の記録を配り直せば同じ局面に戻せる

### 打っている間の見せ方（天鳳・雀魂に倣う）

- **持ち時間**：基礎8秒＋考慮20秒。考慮を使い切ると、その局のあいだは戻らない。
  残り時間はその席の見出しに帯で出て、考慮に入ると朱に変わる。
  時間切れは自分の端末が自分の席ぶんだけ自動で打つ（ツモ切り／スルー）。
  席を外している人のぶんは、部屋を作った人が代わりに打って卓を止めない。
- **手番の光り**：鳴きの受け答え中は、牌を切った席ではなく
  「いま待たれている席」を光らせる。
- **接続待ち**：席を外している人には札を出す。
- **通信の状態**：切れたときだけ卓の上に帯を出し、入り直せるようにする。
  黙って止まると、自分の操作が効かないのか相手を待っているのか分からない。
- **局のはじまり**：何局が始まったかを一度だけ大きく出す。

持ち時間はオンラインのときだけ動かす。ひとりで打つ卓は、待たせる相手が
居ないのに急かす理由がない。

**割り切っていること**：この作りでは、各端末が山と全員の手牌を持つ。
つまり、その気になれば相手の手が見える。友人同士・店内での利用を想定した
作りで、見知らぬ相手との競技には向かない。画面にもその旨を書く。

### 第2段（あとで）：サーバが局を進める

サーバ側で engine を動かし、各席に**見えてよい情報だけ**を配る形。
順位戦や見知らぬ相手との対戦を入れるなら、こちらが要る。

engine は依存が無く、そのまま Lambda に載る。必要なのは
「山と他家の手を伏せた状態」を扱えるようにする改修で、
第1段の通信のしくみ（部屋・席・行動の配布）はそのまま使える。

## 3. 作り

```
[端末] ──WebSocket── [API Gateway] ── [Lambda] ── [DynamoDB]
                                                    部屋・席・行動の記録
```

### メッセージ

| 向き | 種類 | 中身 |
| --- | --- | --- |
| → | `create` | ルール（presetId か rules）を渡して部屋を作る |
| → | `join` | 部屋番号と表示名 |
| → | `start` | 席を締め切って開始（空席はAI） |
| → | `act` | 行動（seat・action・何番目か） |
| → | `resync` | 何番目から取り直したいか |
| ← | `room` | 部屋の状態（席・名前・準備） |
| ← | `begin` | 種・席順・ルール |
| ← | `acts` | 行動の並び（順番つき） |
| ← | `error` | 断った理由 |

### DynamoDB

| pk | sk | 中身 |
| --- | --- | --- |
| `ROOM#<番号>` | `META` | ルール・席・状態・種・TTL |
| `ROOM#<番号>` | `ACT#<連番>` | 行動1件（誰が・何を） |
| `CONN#<接続id>` | `META` | どの部屋のどの席か（切断時の後始末用） |

行動を1件ずつ持つのは、途中から入り直した端末に
「n番目から先」を配り直せるようにするため。

---

## 対局前の確認は、オンラインでは出さない

ひとりで打つときは、卓に入る前に「対局前の確認」（この店で押さえておく点）を
挟んでいる。オンラインでは**これを出さない**。

理由は持ち時間。部屋主が「開始する」を押したあと全員がこの紙を閉じる作りだと、
読んでいる間も自分の持ち時間（基礎8秒＋考慮20秒）が進み、最初の番を
自動で切られることがある。天鳳・雀魂も、部屋が始まったらそのまま卓に入る。

そのぶん、**ルールの要点は「入る前」＝部屋の画面に出す**
（`explainForBeginners` の先頭3件を `.room-rules` として表示）。
部屋に入る／開始するを押す時点で、その卓のルールは読める状態にしてある。

## 2端末での確認記録（2026-08-24）

ブラウザのタブ2つで、実際の AWS WebSocket を通して確認した。

- 部屋を作る → 4桁番号 → もう1台が番号で参加 → 席一覧に両者が出る
- 部屋主が開始 → **両方が確認を挟まずそのまま卓へ**
- 東1局・残り枚数・席順が両方で一致（自分は必ず下辺）
- 片方だけ打ち続けると、もう片方は持ち時間切れで自動的に切られる
- そのあと両方の画面を読み直すと、残り枚数も相手の河の中身
  （6筒 6筒 2筒）も完全に一致していた
