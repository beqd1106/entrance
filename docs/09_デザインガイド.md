# デザイン・UI/UX ガイド

> 目的：**麻雀ガチ勢だけの複雑なツールにしない**。
> 初めての人が「この店で打ってみたい」と思え、雀荘スタッフが自分で設定できるプロダクトにする。
> 本書の内容は実装済み（`web/css/style.css` / `web/js/*.js`）を前提に記述している。

---

## 1. デザインコンセプト

### 一言

**入りやすいオンライン雀荘街**

雀荘の個性と人の温度感は残しつつ、ギャンブル感・怖さ・古臭さを取り除く。
「ルールを検索して比べる便利さ」と「この店で打ってみたい楽しさ」を両立させる。

### 避ける印象 → 目指す印象

| 避ける | 目指す |
| --- | --- |
| 黒背景に金文字、ギラギラ | 白基調・余白多め・軽やか |
| 昭和のゲームUI | 現代のWebサービス／アプリ |
| 情報が詰まりすぎ | 1画面1メッセージ、詳細は折りたたむ |
| 常連にしか分からない | 初来店の人が主役 |
| おじさん向けに閉じた印象 | 若い層・女性・初心者にも開かれた印象 |
| ボタンが小さい・字が細かい | 押しやすい・読みやすい |

### 差別化の軸

既存の麻雀アプリ（暗い卓・写実的な牌・情報過多）とも、
雀荘検索サイト（硬い表組み・テキスト中心）とも見た目で違うこと。
**「店舗ルールを体験するサービス」**という新しさが第一印象で伝わることを優先する。

## 3. フォント方針

| 用途 | 指定 |
| --- | --- |
| 見出し・本文 | `Inter` → `Noto Sans JP` → `system-ui`（サンセリフ統一・字間 `-0.02em`） |
| 数値 | `SF Mono` 等の等幅＋`tabular-nums`（点数が揺れない） |
| **牌の絵柄のみ** | `Noto Serif JP`（明朝）— 萬・字牌の字形はここだけ |

明朝を全体に使うと古く見えるため、**明朝は牌の中だけ**に閉じ込めている。

---

## 4. アイコン方針

- 線画（Tabler / Lucide 相当）を自前SVGで実装。`stroke-width: 1.6`、角丸端点で統一
- **絵文字は使わない**
- アプリアイコンは写実的な牌をやめ、**牌のシルエット＋一筒の同心円**に抽象化
  単色・余白多め・小さいサイズでも identity が残る
- ブランドマークはアプリアイコンと同じ一筒。ナビとアイコンで印象を揃える

## 5. UIトーン＆マナー

| 要素 | 指針 |
| --- | --- |
| 角丸 | 10 / 14 / 20px。ボタンはピル形（999px） |
| 影 | 3段階。ぼかし広め・不透明度低め。硬い影を使わない |
| 余白 | 4/8/12/16/24/32/48/64 の系列 |
| カード | 白面＋1px境界＋淡い影。枠線だけで区切らない |
| アニメーション | 0.15〜0.35s、`cubic-bezier(.22,.61,.36,1)`。意味のある時だけ |
| 見出し番号 | 丸いラベル（`01`）でリズムを作る |
| `prefers-reduced-motion` | 全アニメーションを無効化 |

## 6. ユーザー側の導線

```
トップ
 ├─ ルールから探す（タグを押すだけ）   ← このサービス固有の入口
 ├─ デモ店舗カード
 └─ ルールプリセット
      ↓
店舗一覧（タグで絞り込み）
      ↓
店舗ページ
 ├─ 一般ルールとの差分（既定表示）
 ├─ ルール全文（切替）
 ├─ この店の特別な牌
 ├─ 店舗情報・スタッフ・料金
 └─ イベント卓（そのまま遊べる）
      ↓
【このルールで遊んでみる】   ← 最大のCTA
      ↓
対局前の確認（覚えることは最大5件だけ）
      ↓
対局（CPU3人）
      ↓
結果（役・BP・特殊効果の内訳）
      ↓
店舗ページへ戻る／来店（QRチェックイン）
```

**設計上の判断**：地域検索より**ルール検索を先**に置いた。
地域で探せるサービスは既にあるが、ルールで探せるサービスは無いため。

## 8. 対局画面を現代的に見せるポイント

実装した工夫：

| 課題 | 対応 |
| --- | --- |
| 情報が多い | 卓＝左、ルール要約とログ＝右カラムに分離 |
| 誰の番か分からない | 手番プレイヤーに脈打つドット |
| 直前の打牌が分からない | 最新の捨て牌を枠線でハイライト |
| 押し間違い | **2度押しで確定**（ON/OFF切替可・端末に保存） |
| 何ができるか分からない | 可能な行動だけをボタン表示。役割ごとに色分け（和了＝緑／リーチ＝赤／鳴き＝藍／抜き＝金） |
| 特殊効果が埋もれる | **トースト**で「何が起きたか」を短く提示（2.2秒） |
| 自分の進捗が分からない | 「2向聴」「テンパイ」タグを常時表示 |
| 牌が古臭い | インラインSVGで描画。フラット寄り・白基調・角丸 |
| 抜きドラの混同 | 北・ガリ・華牌を別グループで表示 |
| 知らない牌が来た | **長押し（PCは右クリック）で「この店でのこの牌の意味」**を表示 |
| ドラを見失う | 中央の表示に加え、**手牌のドラが光る**（雀魂を参考に） |
| 何を待っているか分からない | テンパイ時に**待ち牌と残り枚数**。牌を選ぶと「これを切ると何待ちか」 |

## 9. 店舗カードを魅力的に見せるポイント

- 写真枠は**明るいパステル**（店ごとの `--hue` で色が変わる）。暗い写真枠をやめた
- ルールハイライトを**色付きタグ**で並べ、カードを見ただけで店の性格が伝わる
- 初心者歓迎度を星で表示（数値より直感的）
- 1行サマリ（`三麻 / 東風戦 / 35,000/40,000 / 赤4 / 華牌 …`）で情報密度を担保
- ホバーで浮き上がる（触れることを促す）

## 11. スマホ対応（iPhone横持ち前提）

- 横持ちで**卓・河・手牌・行動ボタンが1画面**（844×390で検証済み）
- 縦持ち時は回転をうながす表示
- 手牌と行動ボタンを**画面下に固定**（親指の可動域）
- セーフエリア（ノッチ・ホームインジケータ）を確保
- 牌サイズを役割で分離（手牌30px／河14px）
- PWA対応（ホーム画面追加・オフライン動作）
- iOSアプリ版は横持ち固定・全画面

## 12. アクセシビリティ

- **色だけで判断させない**：ルールタグは色＋文言。牌は色＋字形
- コントラスト：本文は `--ink` on `--paper-2` で十分な比率を確保
- タップ領域：行動ボタンは高さ32px以上、ピル形で間隔を確保
- `prefers-reduced-motion` で全アニメーションを停止
- 牌には `title` 属性で名称（赤5筒・白ポッチ 等）
- 警告はアイコン＋テキスト（色のみに依存しない）

## 16. 第一印象を作り込むための強化

「機能はあるが、見た目が普通」で止まらないために入れた施策。
どれも**設定データから自動的に導く**ので、店舗が増えても素材を用意する必要がない。

### 16-1. 各画面の「主役」を先に決める

| 画面 | 主役 | 主役を支える要素 |
| --- | --- | --- |
| トップ | 「打ってから、行く。」というコンセプト | 特徴的な牌5枚のビジュアル・具体的なルール名 |
| 店舗一覧 | 店ごとの違い | 写真枠の色・ルールタグ・初心者歓迎度 |
| 店舗詳細 | この店で打つ理由 | この店の顔になる牌・ハウスルールの差分 |
| 対局 | 手牌と選択肢 | 卓の面・待ち表示・向聴表示 |
| 対局結果 | 何で和了ったか | 和了形の牌・打点・増減 |
| 店舗管理 | まだ足りない項目 | 進み具合のリング・済み項目は畳む |

### 16-2. 実装した具体策

| 施策 | 内容 | 効果 |
| --- | --- | --- |
| ヒーローの牌ビジュアル | 青5索・白ポッチ・春・赤5筒・北を浮かせて配置 | 文字だけの説明から、扱う対象が一目で分かる画面へ |
| 店舗カードの再設計 | 写真枠に人数／レートのバッジ、地域アイコン、フッターに1行サマリと「遊んでみる」 | 並べたときに店ごとの違いが読める |
| 店舗ページの重ねカード | 写真帯の上に情報カードを −58px で重ねる | 平坦な帯＋白ブロックの構成から脱する |
| 顔になる牌の自動選出 | `signatureTiles(rules)` がルール設定から最大5枚を選ぶ | 店を追加しても画像の用意が不要 |
| 和了形の表示 | 結果画面に手牌＋和了牌（緑で強調）＋鳴きを並べる | 「何で和了ったか」が一目で分かる |
| 卓の面 | 座席の背後に卓布のかたちを敷き、広い画面では卓自体を拡大 | 余白が「何もない場所」ではなく「卓」に見える |
| 特殊牌の説明文 | 効果データから条件と結果を言い切る文章を組み立てる | 「特別な牌です」という無内容な説明を廃止 |
| 説明への牌の同伴 | 各説明の左に、対局で出てくるのと同じ牌を置く | 言葉より速く伝わる |
| 公開前チェックの畳み方 | 未完了は大きく・済みは4列グリッドへ | 手を動かす項目だけが目に入る |

### 16-3. 特殊牌の説明文の作り方

`specialTileSentence(def)`（`src/rules/explain.js`）が、条件と効果から1文を組み立てる。

```
条件：menzenOnly, riichiOnly, tsumoOnly, ronOnly, ippatsuOnly
  → 「門前のとき、この牌を持っていると」
効果：dora / han / bonus / rankUp / almighty / doubleDora /
      bonusMultiply / scoreMultiply / yakuman / alice / dice / ura
  → 「1翻ぶん打点が上がります」「好きな牌の代わりとして使えます」
```

出力例：

- 銀5筒（シルバー）— この牌を持っているとドラ2枚分になります。
- 翠5萬（エメラルド）— 門前のとき、この牌を持っていると1翻ぶん打点が上がります。さらにボーナスポイントが3もらえます。
- アメジスト5筒 — リーチしているとき、この牌を持っているとボーナスポイントが5もらえます。さらに好きな牌の代わりとして使えます。

店舗が独自の `description` を書いた場合はそちらを優先する。
書かなくても成立することが重要で、**説明文の記入を公開の条件にしない**。

### 16-4. やらないこと

- 写実的な牌画像・木目の卓・金色の装飾（古い麻雀アプリの記号になる）
- 意味のないパララックス、スクロールに連動する派手な演出
- store ごとの手描きイラスト（運用が破綻する。色とマークとルール由来の牌で代替）
- 「かっこよさ」のために情報を削ること（UX最優先の原則は変えない）

### ■ 追記セクション：デザイン・UI/UX 要件

**方針**
既存の麻雀アプリ（暗い卓・写実的な牌・情報過多）とも、雀荘検索サイト（硬い表組み）とも
**一目で違うと分かる**見た目にすること。ポップ・モダン・シンプル・親しみやすさを優先し、
黒×金・昭和ゲームUI・ギャンブル色の強い表現は使わないこと。

**1. カラー**
白／オフホワイトを土台に、エメラルドを主アクセントとする。濃色は対局卓のみ。
ルールタグは意味ごとに色調を割り当てる（白ポッチ=sky／アリス=coral／華牌=amber／
五等サンマ=teal／特殊牌=violet／初心者歓迎=mint／割れ目=rose）。
**色だけで意味を判断させない**（必ず文言を併記する）。

**2. フォント**
見出し・本文はサンセリフで統一し、字間を詰める。明朝は**牌の絵柄の中だけ**に限定する。
数値は等幅＋`tabular-nums` で桁を揃える。

**3. アイコン**
線画で統一し、**絵文字は使わない**。アプリアイコンは写実的な牌ではなく、
牌のシルエット＋一筒などの記号に抽象化する。ブランドマークとアプリアイコンを揃える。

**4. ユーザー導線**
トップに「**ルールから探す**」を置き、地域検索より前に配置すること。
店舗ページの最大のCTAは「このルールで遊んでみる」とし、1タップで対局に入れること。

**5. 対局前の確認画面**
対局を始める前に、その店で覚えるべき点を**最大5件**、平易な日本語で提示すること。
専門用語はかみ砕く（例：「白ポッチ＝白に赤い点が付いた特別な牌。リーチ後のツモのとき好きな牌として使えます」）。

**6. 対局画面**
・可能な行動だけをボタン表示し、役割ごとに色を分ける（和了／リーチ／鳴き／抜き）
・**打牌は2度押しで確定**（誤タップ防止。ON/OFF切替可）
・手番・直前の打牌・自分の向聴数を常時わかるようにする
・特殊効果の発動は**トースト**で短く提示する（派手にしすぎない）
・抜きドラ（北・ガリ）と華牌は別グループで表示し、混同させない

**7. スマホ（iPhone横持ち前提）**
横持ちで卓・河・手牌・行動ボタンが**1画面に収まる**こと。
手牌と行動ボタンは画面下に固定し、セーフエリアを確保すること。
縦持ち時は回転をうながすこと。PWAとしてホーム画面に追加でき、オフラインで動作すること。

**8. 店舗管理UI**
JSON・Validator・Schema等の技術用語を画面に出さないこと。
設定は3段階（初級＝プリセット選択／中級＝ON/OFFスイッチ／上級＝WHEN-IF-THEN）に分け、
右側に常に「お客様向け説明のプレビュー」と「設定チェック」を表示すること。
公開前チェック（入力漏れ・矛盾・試し打ち・非換金確認）を用意すること。

**9. アクセシビリティ**
色だけに依存しない／タップ領域を広く／`prefers-reduced-motion` に対応／
牌に名称のラベルを持たせる／警告はアイコン＋テキストで示す。

**10. 素材生成**
必要に応じて画像生成AI等でイラスト・アイコンを作ってよい。ただし
**情報設計と使いやすさを優先**し、イラストが無くても成立する設計を保つこと。
装飾過多にせず、UIに馴染むフラット寄り・ポップな方向で統一すること。

**11. 完成条件**
初心者が店を探せる／ルールの違いが分かる／店舗側が自分で登録できる／
特殊ルールが視覚的に分かる／スマホで操作しやすい／
提案時に3〜5分で価値が伝わる／雀荘らしさはあるが怖くない／
「ルール体験から来店」という本質が見た目からも伝わること。

## 12. 卓の画面：天鳳・雀魂に合わせたところ／あえて合わせないところ

打っている最中の画面は、既存の麻雀ゲーム（天鳳・雀魂）を見慣れた人が
迷わないことを最優先にする。以下は実機で見比べて決めたもの。

**合わせたところ**

| 決まりごと | なぜ |
|---|---|
| 河は6列で折り返す | 何巡目に何を切ったかが読める。1行に伸ばすと巡目が分からない |
| リーチ宣言牌を横に倒す | どこで曲げたかが河を見れば分かる |
| 鳴いた牌を横に倒し、倒す位置で出どころを示す（上家＝左端・対面＝真ん中・下家＝右端） | 誰が振り込んだのかを卓の上から追える |
| 暗槓は両端を伏せ、中の2枚を表にする | 何を槓したのか・ドラが増えた理由が追える |
| 供託のリーチ棒を卓の中央に置く | 場にいくら乗っているかが分かる |
| 自分の席を必ず下辺に置く | 席が変わっても見え方が変わらない |
| いま誰の番か・リーチ中かは名札の色で示す | 席そのものを囲むと、上下の席は卓の幅いっぱいなので画面を横切る帯になる |

**あえて合わせていないところ**

- **牌山（伏せ牌の輪）を描かない。**
  天鳳・雀魂は卓のまわりに牌山を並べるが、iPhone の横持ち（高さ375〜430px）で
  4人ぶんの河（1人あたり3〜4段）を切らさずに置くと、牌山を入れる高さが残らない。
  残り枚数は卓の中央に数字とゲージで出しているので、情報としては足りている。
  高さに余裕のある画面（iPad 等）で描くかどうかは、河の高さを削らずに置けると
  確かめてから決めること。

- **他家の伏せ手牌を横持ちでは畳んでいる。**
  何を持っているかは見えないので情報量が無い。そのぶんの高さを河と鳴きに回す。

**画面まわりで踏んだ罠（同じことを繰り返さないために）**

- `.board-scroll` を `display: grid; justify-content: center` にすると列が中身なりになる。
  卓の `max-width: 100% - 118px` の 100% がその列を指してしまい、828px 使える画面で
  卓が 275px まで縮んでいた。脇のメニューぶんは **卓の幅から引かず、
  親の padding で空ける**こと。
- 3行のうち真ん中を `auto` にすると、左右の席の中身ぶんが中央行に取られ、
  上下の席の河が切れる。**3行は等分**にして、名札は河の上ではなく横に置く。
- `.act` は緑の卓の上に置く前提の色（白い文字・うっすら白い地）。
  白い紙（sheet）の中で使うときは紙用の色に切り替えること。
